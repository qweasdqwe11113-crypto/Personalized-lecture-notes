# 知页使用指南

本指南面向使用知页备课的老师，按实际操作顺序说明：安装 → 连接模型 → 准备课程、班级和学生 → 生成讲义 → 出题、课件与授课包 → 阅卷并记入画像 → 数据备份与升级。各功能的详细规则见 [features.md](features.md)。

> 讲义、题目、课件和评分建议都由模型生成。程序只检查结构、篇幅和引用编号，不能保证内容正确，上课和记分前请逐项核对。

## 一、安装与第一次启动

### 选哪个版本

| 版本 | 适合 | 第一次打开时 |
| --- | --- | --- |
| **知页**（正式版） | 正式使用 | 空白，从建课程开始 |
| **知页测试版** | 先试用、熟悉功能 | 带两门演示课程、两个演示班级和 6 名虚构学生 |

两个版本可以同时安装，数据完全分开，互不影响。测试版里的内容不能转到正式版。

### 下载与安装

安装包在项目的 GitHub Releases 页面下载（文件名中的 `0.1.0` 是版本号）：

| 系统 | 正式版 | 测试版 |
| --- | --- | --- |
| Windows | `zhiye-0.1.0-win-x64.exe` | `zhiye-test-0.1.0-win-x64.exe` |
| Linux | `zhiye-0.1.0-linux-x86_64.AppImage` 或 `zhiye-0.1.0-linux-x64.tar.gz` | 文件名以 `zhiye-test-` 开头 |

- **Windows**：双击安装程序，按提示选择安装位置。安装包没有代码签名，第一次运行如果出现「Windows 已保护你的电脑」，点「更多信息」→「仍要运行」。安装后桌面和开始菜单都有「知页」图标。
- **Linux（AppImage）**：下载后先赋予执行权限，再双击或在终端中运行：

  ```bash
  chmod +x zhiye-0.1.0-linux-x86_64.AppImage
  ./zhiye-0.1.0-linux-x86_64.AppImage
  ```

- **Linux（tar.gz）**：解压后运行其中的 `zhiye`（测试版为 `zhiye-test`）。

数据库和运行环境都随程序安装，不需要另装 Python 或 PostgreSQL，也不需要使用命令行。

### 第一次启动

打开后先出现启动页，依次完成四步：检查数据目录 → 启动本机数据库 → 准备数据表 → 启动教学服务。第一次需要建立数据库，大约多等几秒；之后会自动进入「讲义工作台」。

正式版第一次进入工作台时，会先出现 **新手引导**：页面变暗，只亮出一处，旁边说明它的用途，共 8 步，依次介绍左侧导航、课程与班级切换、系统设置、课程和学生、生成讲义的位置、出题与阅卷，以及「开始使用」清单。点「下一步」翻页，也可以用键盘 ← → 翻页、Esc 跳过。看完或跳过后不会再自动出现；想再看一遍，点左侧导航下方的 **「新手引导」**，或菜单「帮助」→「新手引导」。测试版不会自动弹出，但同样可以从这两处打开。

正式版的工作台顶部有一个 **「开始使用」** 引导，列出五步：连接语言模型、新建课程、建立知识点库、添加班级和学生、新建备课。每完成一步自动打勾，全部完成后自动隐藏；也可以点「收起」先折叠。下面第二、三节就是这五步的详细说明。

如果启动页显示失败，页面上会写明原因和建议，可以「重试」「查看日志」「打开数据目录」或「更换数据目录」，见[常见问题](#八常见问题)。

## 二、连接语言模型（必做）

讲义、出题、阅卷和资料识别都要调用模型。知页本身不带模型，需要连接一个 **OpenAI 兼容接口** 的模型服务：云服务（如阿里云百炼）或本机运行的 Ollama 都可以。

### 打开设置

左侧导航点 **「系统设置」**，可以看到三个模型：

| 模型 | 是否必需 | 用途 |
| --- | --- | --- |
| 01 语言模型 | **必需** | 生成讲义、题目、课件，阅卷评分，识别资料中的知识点 |
| 02 视觉模型 · VLM | 可选 | 识读上传资料中的图片；阅卷时识读试卷照片和扫描件 |
| 03 嵌入模型 · Embedding | 可选 | 「向量检索」方式取用资料时使用；默认的「精确 SQL」不需要 |

### 填写与测试

每个模型都填三项：

- **服务地址**：基础地址，通常以 `/v1` 结尾。
- **模型名称**：服务商提供的模型 ID。
- **API 密钥**：服务商提供的密钥。本机 Ollama 一般不需要密钥，可以留空。

常见填法示例：

| 服务 | 服务地址 | 模型名称示例 |
| --- | --- | --- |
| 阿里云百炼 | `https://dashscope.aliyuncs.com/compatible-mode/v1` | 语言模型 `qwen3.8-max`，视觉模型 `qwen3.8-flash`，嵌入模型 `text-embedding-v4` |
| 本机 Ollama | `http://127.0.0.1:11434/v1` | 已下载到本机的模型名，如 `qwen3.5:9b` |

使用百炼时，一个 API 密钥可以同时用于三个模型。

填好后按顺序操作：

1. 点每个模型下方的测试按钮（「测试文本生成」「测试图片识别」「测试向量接口」），确认显示成功。测试会真正调用一次模型。
2. 点 **「保存配置」**。
3. 点页面上出现的 **「立即重启服务」**，大约几秒后生效。正在运行的生成任务会被中断，所以最好在没有任务时重启。

密钥只保存在本机的数据目录中，页面上不会再显示原文。之后想换密钥，直接填新的；留空表示保留原密钥；勾选「清除已保存密钥」则删除。

> **数据会发给谁**：所有数据都保存在本机。只有在生成讲义、出题、阅卷或识别资料时，才会把这次需要的资料、学生画像和要求发送给你配置的模型服务。使用云服务前，请确认学校对学生信息外发的要求。

## 三、准备课程：知识点、班级、学生、备课

层级关系：**课程 → 班级 → 学生**。每门课程有自己的知识点库、资料、备课和班级。页面顶部的 **「课程 › 班级」** 下拉框决定当前在哪门课、哪个班，讲义工作台、出题、阅卷等页面都跟着它切换。

### 1. 新建课程

左侧点 **「课程」** → 右上角 **「全部课程」** → **「新建课程」**，填写课程名称（如「高等数学」）、学段（如「大学」）和课程说明（选填），点「创建课程」。可以建多门课程，在顶部随时切换。

### 2. 建立知识点库

知识点是诊断学生和组织讲义的基本单位，一门课程的所有备课共用一个知识点库。进入 **「课程」→「知识点库」**，有两种方式建立：

- **逐条添加**：点「新增知识点」，填写名称和所属章节（如「第二章 数列极限」）。
- **上传资料，自动识别**（推荐，需要已配置语言模型）：
  1. 进入 **「课程」→「课程资料」**，点「上传资料」，选择讲义、教材或课件。支持 TXT、MD、PDF、DOCX 和图片，每份最多 10 MB，PDF 最多 200 页；也可以切到「网址上传」导入公开网页。扫描版 PDF 没有文字层，需要先做 OCR；图片和扫描件可以点「图片识读」，由视觉模型解析。
  2. 上传后系统自动识别知识点，资料行会显示进度；也可以手动点「识别知识点」或「重新识别」。
  3. 识别结果只是草稿。点 **「审核并确认」**，逐条检查名称和对应页码，可以改名、调整页码范围、「并入上一条」、删除或新增，然后确认。
  4. 确认后，每个知识点都带上对应的那段资料。之后生成讲义时，会自动引用这些资料。

名称只差全角半角、空格或大小写的，视为同一个知识点（如「泊松分布(poisson)」和「泊松分布（Poisson）」），不会重复建立。不再使用的知识点可以「归档」，历史记录不受影响。

### 3. 新建班级、添加学生

- **新建班级**：**「课程」→「班级」→「新建班级」**。一个班级只属于一门课程。
- **添加学生**：顶部切到这个班，左侧点 **「班级与画像」**，然后：
  - **「新建学生」**：逐个填写姓名、年级或说明、学习特点；
  - **「添加已有学生」**：把其他课程里已有的学生加进本班。同一名学生可以同时上多门课，但在同一门课中只属于一个班；
  - **「批量导入」**：先选导入内容，点「下载 CSV 模板」，用 Excel 填好后上传，点「预览导入」逐行核对，再「确认导入」。

批量导入有两种表格：

| 导入内容 | 模板的列 |
| --- | --- |
| 学生名单 | 姓名、年级或说明、学习特点 |
| 学习证据 | 学生姓名、知识点、证据来源、任务或观察内容、学生表现、观察日期、判断（更新状态 / 保留原判断）、新掌握状态、确认理由 |

导入时注意：

- 文件可以是 UTF-8 编码，也可以是 Excel 默认的 GBK 编码，每次最多 300 行。
- 只要有一行出错，整批都不导入。
- 学生名单中，本班已有同名学生会跳过，不会覆盖原档案。
- 学习证据中的知识点名称，要和本课程知识点库里的名称对应。写错时，预览会提示相近的名称。

### 4. 学生画像与班级画像

讲义会参考学生的画像，所以画像越准确，讲义越贴合学生。

- **学生档案**：在学生名单中点开某名学生，可以「编辑学生画像」（姓名、学生说明、学习特点），所有修改都会保留历史。
- **记录诊断证据**：在学生档案的「知识点掌握情况」中，点「记录诊断证据」，录入作业、测验或课堂观察的表现，由你确认掌握状态：已掌握、部分掌握、需要补充或未知。**模型生成的内容永远不会自动改变学生的掌握状态**，只有老师确认的证据才会写入。
- **班级画像**：在「班级与画像」→「班级画像」中，按知识点汇总全班的掌握情况，显示需要重点关注的学生。也可以填写「班级特点」，生成全班讲义时会用到。

### 5. 新建备课

**「课程」→「备课」→「新建备课」**，主要填写：

- **章节**、**备课名称**、**教学目标**、**教案 / 备课正文**（都可以先留空，之后再补）；
- **知识点**：从知识点库中勾选，最多 20 个。勾选后，这些知识点已确认的资料会自动成为本备课的参考资料；
- **新增知识点**：每行写一个，保存时自动加入知识点库。

点「保存备课」。备课属于整门课程，本课程所有班级都能用；具体为全班还是为某个学生生成，到生成讲义时再选。

## 四、生成讲义

左侧点 **「讲义工作台」**。

1. **选择备课与讲义对象**：讲义对象可以选「全班」，按班级画像生成，不发送学生姓名；也可以选某一名学生，按他的个人画像生成。
2. **本次怎么讲**：授课时长（5—180 分钟）、课型（新授 / 巩固 / 纠错 / 复习）、讲解详略、完整例题数（0—6）、课堂练习数（0—10）。页面会按时长给出篇幅建议，例如常规 45 分钟大约 3600—5400 字。
3. **本次讲解安排**：按知识点列出诊断依据和建议讲法，可以逐项修改。这里的修改只用于这一份讲义，不会改动学生的长期画像。
4. **高级设置**（可不改）：
   - 是否使用学生画像；
   - 资料取用方式：「精确 SQL」或「向量检索」，向量检索需要嵌入模型；
   - 写作方式：默认「先做课堂设计，再按环节写」，见下面的「确认课堂设计」；旧版「先列大纲，再分章节写」和「一次写完整篇」仍可选；
   - 写详案前先让我确认课堂设计：默认勾选；
   - 公式格式：默认支持公式与程序绘制的图。
5. **图片解析依据**（选填，最多 4 条）和 **备注**（选填）。
6. 点 **「生成个性化讲义」**。生成在后台进行，右侧会实时显示正在写的内容，一般需要一到几分钟。生成过程中可以切换到其他页面。

### 确认课堂设计

默认的写作方式分两步。第一步只出一份 **课堂设计**，完成后弹出「确认课堂设计」窗口：

- **左边是设计内容**：重点、难点、本课不展开的内容、学习目标（每条注明由哪道题检验）、课堂流程表（时间、环节、教师、学生、板书），以及全课的例题、当堂练习和课后作业。
- **右边可以调整**：各环节的分钟数（下方显示合计与授课时长是否一致）、重点难点、每道题的题干和答案。改完点「应用修改并检查」。
- **上方的黄色提醒**来自程序检查，例如「各环节合计 43 分钟，授课时长是 45 分钟」「有 3 道当堂练习却只有 6 分钟」。提醒不阻止你继续，是否调整由你决定。
- 想大改时，在「让模型按意见重做」里写一句话（例如「例2 换成教材里的保险题；方差的推导不讲」），点「按意见重做设计」。
- 满意后点 **「确认设计，写教师详案」**，第二步才开始写正文。

关掉窗口不会丢失设计：在左侧「生成记录」→「后台任务」里点「课堂设计 · 待确认」可以重新打开。

这样生成的讲义按课堂环节排列：先是「本课要点」和课堂流程表，然后每个环节一节（屏幕、板书、讲解要点、提问与预期回答、例题和练习），最后是板书设计和课后作业。题目只写一次，各处引用的是同一份。

不想每次确认，可以在高级设置里取消勾选「写详案前先让我确认课堂设计」。批量生成不会停下来确认。

### 阅读、修改与导出

- 正文中的 `[M编号]` 表示引用的课程资料，点击可以查看原文；正文上方是程序检查的摘要。
- **编辑与审核**：修改正文后，会另存为 R1、R2 等新版本，原稿保留。全部检查项确认后，可以标记为「教师已审核」。
- **按章节调整**：只重写某一章节（按课堂设计生成的讲义是某一个环节），可以展开、简化、更换例题，或写自定义要求。生成后对照前后内容，满意再采用。
- **导出**：可以下载 Word（公式可编辑）、网页、Markdown、纯文本，或用「打印 / PDF」导出。
- **批量生成**：「为班内学生逐个生成」，按当前设置为多名学生各生成一份，一次最多 60 人。
- 生成失败时，页面会显示失败原因，可以「按原输入重试」。所有讲义都在左侧 **「生成记录」** 中。

## 五、出题、课件与授课包

打开一份讲义后，工具栏的 **「授课准备」** 一组有三个按钮：

- **配套出题**：按这份讲义出练习题，题目的方法和符号与讲义一致。
- **生成授课 PPT**：设置页数（6—20 页，默认 12 页）和要求，生成可编辑的 PPTX，逐页讲稿放在备注里。不满意的页可以点「修改这一页」单独重做，满意后「采用并保存新版本」。
- **导出授课包**：打包成一个 ZIP，包含教师授课手册（Word）、不含答案的学生练习、练习教师版、讲义正文和课件。导出授课包不会调用模型。

也可以不依赖讲义，直接在左侧 **「出题」** 页出题：

- 选择备课、参考对象（全班、某名学生或通用水平）、学生水平；
- 题目数量（1—30）、难度（基础、中等、拔高或混合）、题型（单选、填空、简答、计算、综合应用）；
- 点「生成练习题」。

每道题都附参考答案、解析和易错点，学生版和教师版分别下载。**题目答案可能有错，请逐题核对。**

## 六、阅卷并记入学生画像

左侧点 **「阅卷」**：

1. **上传学生作答**：支持图片、PDF、Word、TXT、Markdown。每次合计 10 MB，最多 30 题，每份最多 8 张图片或 8 页 PDF。试卷照片和扫描件需要配置视觉模型。
2. **选择参考答案来源**（三选一）：
   - **使用系统题组的教师版答案**（推荐）：选择学生作答对应的题组。评分后可以按知识点记入学生画像；
   - **上传参考答案文件**：答案和评分标准可以放在同一份文件里；
   - **由模型推导答案**：没有答案时使用，评分会标为推导答案，需要重点核对。
3. 点 **「上传并自动阅卷」**。完成后逐题显示学生作答、参考答案、建议得分和错因；识读不清的题目标为「待核对」，不计分。
4. **记入学生画像**：选择这份作答对应的学生，系统按知识点整理出证据草稿。你可以修改表现描述，选择「更新状态」或「保留原判断」并写明理由，**逐条点「确认记录」后才会写入**。下次为这名学生生成讲义时，就会用到新的诊断。

建议得分只是参考，最终分数以老师判断为准。

## 七、数据、备份与升级

### 数据在哪里

所有数据都保存在本机，包括数据库、上传的资料、阅卷记录和模型配置：

| 系统 | 正式版 | 测试版 |
| --- | --- | --- |
| Windows | `%LOCALAPPDATA%\Zhiye` | `%LOCALAPPDATA%\Zhiye-Test` |
| Linux | `~/.local/share/zhiye` | `~/.local/share/zhiye-test` |

可以通过菜单 **「服务」→「打开数据目录」** 直接打开。

### 「服务」菜单

| 菜单项 | 作用 |
| --- | --- |
| 重启服务 | 修改模型配置后，或页面长时间没有响应时使用 |
| 在浏览器中打开 | 用系统浏览器打开同一个工作空间，数据相同 |
| **备份数据** | 暂停服务，把数据库、上传资料、阅卷记录和模型配置复制到你选择的位置，生成一个「知页备份-日期时间」文件夹，完成后自动恢复服务 |
| **从备份恢复** | 选择一个备份文件夹恢复。当前数据不会被删除，而是移到数据目录下的「恢复前-日期时间」文件夹 |
| 打开数据目录 / 查看日志 | 排查问题时使用；反馈问题时请附上日志 |
| 更换数据目录 | 把以后的数据存到别的位置（原目录不会被删除或移动）。想沿用原数据，先备份，再到新目录中「从备份恢复」 |

**建议定期备份**，特别是在升级之前，或者录入了大量学生数据之后。备份只能恢复到同一个版本：正式版的备份恢复到正式版，测试版的备份恢复到测试版。备份中含有学生资料和已保存的 API 密钥，请妥善保管，不要上传到公开位置。

### 升级与卸载

- **升级**：菜单「知页」→「检查更新」，发现新版本后会打开下载页。下载新的安装包，直接安装即可，原有数据会保留。
- **关闭**：直接关闭窗口。窗口会显示「正在安全关闭数据库与服务…」，停好后自动退出，通常几秒，期间不要强制结束进程。
- **卸载**：卸载程序不会删除数据目录。如果确定不再需要这些数据，再手动删除上表中的文件夹。

## 八、常见问题

**「生成个性化讲义」按钮是灰的**

按顺序检查：

1. 语言模型是否已配置并重启服务（工作台顶部的引导第一步是否已打勾）；
2. 是否选择了备课：当前课程还没有备课时，到「课程」→「备课」新建；
3. 当前班级是否有学生：可以先选「全班」，或到「班级与画像」添加学生；
4. 备课是否有资料或教案：页面会提示「当前备课尚无课程资料」。勾选已有资料的知识点、上传资料，或者在备课里写上教案正文，都可以解决。

**模型测试成功，但生成失败**

到「生成记录」里查看失败原因。常见原因有：模型服务超时、余额不足、模型返回的格式不符合要求。可以「按原输入重试」。如果反复因为篇幅或格式失败，可以换一个能力更强的语言模型。

**启动页显示「启动本机数据库失败」**

- 检查数据目录所在磁盘是否已满；
- 检查杀毒或安全软件是否拦截了 `postgres.exe`；
- 数据目录的路径中，是否有系统无法识别的特殊字符。

可以先「重试」，不行就点「更换数据目录」，换到另一个文件夹。

**提示端口被占用**

知页优先使用固定端口（正式版 38660，测试版 38661）。这个端口被其他程序占用时，会自动改用空闲端口，不影响使用：数据、顶部选中的课程和班级都保存在本机数据库里，换端口后照旧。

**Linux 上打不开，或日志提示「不使用沙箱运行」**

Ubuntu 24.04 起，系统限制了浏览器沙箱。知页会自动改为不使用沙箱启动，并在日志里记一行说明。使用 tar.gz 版的话，可以在程序目录里运行下面的命令，之后就会重新启用沙箱：

```bash
sudo chown root:root chrome-sandbox && sudo chmod 4755 chrome-sandbox
```

**Windows 提示「Windows 已保护你的电脑」**

这是因为安装包没有代码签名。点「更多信息」→「仍要运行」即可。

**可以几台电脑共用同一份数据吗？**

不可以同时使用。数据库只在本机运行。换电脑时，在旧电脑上「备份数据」，把备份文件夹拷到新电脑，再「从备份恢复」。

**遇到其他问题**

通过菜单「帮助」→「问题反馈」提交问题，描述你的操作步骤，并附上「服务」→「查看日志」中的最后几十行。问题反馈是公开的，贴日志前请删去学生姓名等个人信息。
