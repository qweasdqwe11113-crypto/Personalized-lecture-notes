# 规模数据与评测基线

预置数据很小：6 名学生、6 个知识点、6 段材料。材料最长的一段也短于向量检索的分块长度（500 字符），每门课只有 3 个片段，而向量检索取前 6 段——结果必然与「全部关联材料」完全相同，检索对比没有意义；16000 字符的材料预算也从未触发。`demo/scale/` 用来补上这一块，全部是可选的，不运行就不影响现有数据。

## 内容

| 文件 | 作用 |
| --- | --- |
| `corpus/linear_equations.json`、`corpus/conditional_probability.json` | 两门整章课程，各 12 个知识点。每个知识点有一段自编讲解（概念、依据、常见错误）和 2 条带标注的教学问题 |
| `examples.py` | 按知识点类型生成例题与检验。所有数字用精确分数计算，同一随机种子输出相同文本 |
| `load.py` | 把语料装进数据库并生成合成班级；`--remove` 删除它创建的数据 |
| `eval_retrieval.py` | 检索评测，不需要数据库 |
| `bench.py` | 生成基准，在一次性的隔离库里运行 |

语料是自行编写的讲解加程序计算的例题，不是教材原文；主题参照预置材料所用的 OpenStax 章节范围。讲解中的数字例子（如基础率示例）均为假设。

## 装载与清除

```bash
.venv/bin/python demo/scale/load.py                          # 两门课 + 每门课 40 名合成学生
.venv/bin/python demo/scale/load.py --students 12 --examples 4
.venv/bin/python demo/scale/load.py --remove
```

- 装载后在「讲义工作台」的备课副本里会多出「一元一次方程整章（扩展语料）」和「条件概率与贝叶斯整章（扩展语料）」。默认每个知识点 8 道例题，两门课约 1.4 万和 2.4 万字符。
- 合成学生的副标题以「合成·」开头。每人按能力层次（基础待巩固 / 常规 / 学有余力）和知识点在章节中的位置抽样出掌握状态，约 15% 的知识点没有证据（保持「未知」）。证据通过与教师逐条录入相同的确认路径写入，记录者为「合成数据脚本」。这些状态是抽样得到的，不是观察结果。
- 重复运行不会重复装载。`--remove` 只删除带标记的数据；已经有讲义、生成记录或题组的合成学生会保留并列出，因为这些记录引用了他们。
- 自建备课副本对全部学生可用，所以合成学生也会出现在其他备课副本的学生列表里。

## 检索评测

```bash
.venv/bin/python demo/scale/eval_retrieval.py                  # 离线，哈希向量
.venv/bin/python demo/scale/eval_retrieval.py --embedder qwen  # 已配置的嵌入模型（真实调用，约 400 段文本）
```

对每门课，把整章的全部片段按每条问题排序，命中指排在前 k 的片段里有属于该问题所在知识点的片段。比较三种排序：应用现在使用的向量余弦、字符二元组 BM25、两者的倒数排名融合。输出 recall@1/3/6、MRR 和前 6 段中命中片段的比例。

离线哈希向量只反映字面重合，那一行不能说明语义检索的效果；它的用处是让脚本不联网也能跑通，并给 BM25 一个参照。要评价真实的嵌入模型请加 `--embedder qwen`。

注意应用里的向量检索只在所选知识点内排序，这里是在整章范围内排序，题目更难，用来回答「如果以后改成按章节检索，够不够用」。

## 生成基准

```bash
.venv/bin/python demo/scale/bench.py                                   # 模拟模型，12 份讲义，并发 1 与 3
.venv/bin/python demo/scale/bench.py --jobs 40 --latency 8 --concurrency 1 3 6
.venv/bin/python demo/scale/bench.py --real --jobs 2 --concurrency 3  # 真实模型，会产生费用
```

脚本像测试一样在专用数据库里建一个临时 schema，装入扩展语料和合成班级，通过真实的批量接口、队列、并发闸门和存储代码生成讲义，结束后删除这个 schema。

- **模拟模式**只替换模型调用：等待 `--latency` 秒后返回一份达到篇幅要求的回复。它衡量的是流水线本身（排队、并行写章节、检查、保存），不反映模型质量。
- **`--real`** 不替换模型调用，并额外统计每份讲义的汉字数、篇幅检查通过率、各项程序检查的提示次数和平均 token 用量；讲义和结果保存在 `.runtime/bench/<时间>/`。

本机一次模拟运行的结果（条件概率整章，材料 24469 字符，6 份讲义，每次调用 0.5 秒）：并发 1 用时 18.4 秒，并发 3 用时 6.3 秒，快 2.9 倍；每份讲义的输入约 3.6 万字符。真实模型下的篇幅达标率还没有测过，需要用 `--real` 运行后才能下结论。
