# Prompt 与实际输入

知识点识别现用 [knowledge-recognition-v2.md](knowledge-recognition-v2.md)，输入结构为 `knowledge-units-v2`：在 v1 的基础上多送本课程知识点库已有的名称（`library`，最多 400 个），要求资料讲的是已有知识点时逐字沿用原名，避免同一概念在库中出现多个近似名称；历史草稿记录的 v1 模板保持不变。v1（[knowledge-recognition-v1.md](knowledge-recognition-v1.md)，`knowledge-units-v1`）的输入为：课程名称与学段、资料标题、程序找到的编号小节（`sections`），以及按页（PDF）或按段切分、去掉页眉页脚后的正文（`units`，目录页只送 200 字并标 `contents_page`；正文合计约 60000 字，按单元平均分配）。请求使用 JSON 模式、关闭思考，输出为章名和带页码范围的知识点。结果只是草稿，教师确认前不写入知识点库；请求的 SHA-256 记在 `knowledge_drafts.input_sha256`。

授课课件使用独立模板 [lecture-ppt-v1.md](lecture-ppt-v1.md)，输入结构为 `lecture-ppt-context-v1`。实际发送的是所选已保存讲义、教学目标、授课设置、材料及课件要求，不额外发送学生画像、诊断或本次观察字段。该模板要求简洁投屏内容与详细逐页教师讲稿分开，使用固定页数和可读 Unicode 公式；后台对 JSON 结构、文字预算、封面、末页总结及 M/V 来源编号进行检查。程序检查不替代教师对课件正确性及教学可用性的审核；原讲义中的个体描述仍应在内容复核时检查。

当前初中模板为 [lecture-math-v3.md](lecture-math-v3.md)，大学模板为 [lecture-probability-v2.md](lecture-probability-v2.md)，新讲义输入结构为 lecture-context-teacher-v2，追加 [lecture-plan-v1.md](lecture-plan-v1.md) 的可编辑教学安排及定位要求；旧结构仍按原字节保存。此前 math v1 / v2、大学 v1 保持已使用正文。运行 #1 是 math v1 / context-v2，#2 是 math v2 / context-v3，大学固定对照 #3—#14 是 probability v1 / context-v4，后续 #15 / #16 使用 probability v2。旧输入不因更新模板而重建。

## 课堂设计方式（默认）

「先做课堂设计，再按环节写」（`generation_mode=designed-v1`）使用单独的一套提示词，不在上面的模板后面叠加覆盖条款：

| 文件 | 用在哪里 | 内容 |
| --- | --- | --- |
| [lecture-design-base-v1.md](lecture-design-base-v1.md) | 设计与环节两个阶段 | 输入各字段的含义、范围与依据、学生情况怎么用、三份配套材料共用一套题目和符号、备课笔记的写法 |

| [lecture-subject-math-general-v1.md](lecture-subject-math-general-v1.md)、[lecture-subject-probability-general-v1.md](lecture-subject-probability-general-v1.md) | 老师自建的备课，课程学科为数学或概率统计时附加（各写作方式都加） | 学科通用的要求：每步依据与前提、验算；事件定义、概率范围、条件概率与公式的成立条件、数值复算。版本后缀 `+math-general-v1` / `+probability-general-v1` |
| [lecture-design-plan-v1.md](lecture-design-plan-v1.md) | 设计阶段（冻结的请求） | 设计的思考顺序、时间与题量规则、JSON 格式与各字段说明、公式与图的写法 |
| [lecture-design-segment-v1.md](lecture-design-segment-v1.md) | 环节阶段 | 只写设计里没有的内容：怎么讲、哪一步提问、怎么纠错、怎么分层；不重抄题目 |

| [lecture-retrieval-v1.md](lecture-retrieval-v1.md) | 设计与环节两个阶段，只在材料取用方式为整门课检索（`retrieval_mode=hybrid`）时附加，版本随之带 `+lecture-retrieval-v1`；旧版写作方式（一次写完、分章节）也附加 | 材料是整门课里检索到的节选（以「……」相连），`use` 写明讲解依据、例题练习、针对学情或教师保留；改编的例题写「改编自 [M编号]」；与本课无关的片段可以不用；自己的知识不标 [M编号] |

版本标记为 `lesson-design-v1`（概率、初中方程带 `+probability-v1` / `+math-v1`，一对一辅导带 `+tutor-v1`，按教师意见重做时带 `+revision`），输入结构为 `lesson-design-context-v1`。环节请求为 `lesson-segment-v1`，重写为 `lesson-segment-repair-v1`，设计有结构问题时整份重做，版本为 `lesson-design-repair-v1`；只有提醒时局部修正，版本为 `lesson-design-patch-v1`。环节阶段的完整系统提示在提交时写入冻结上下文的 `designed.segment_system`，所以重试不受之后模板改动的影响。

模型看到的上下文由 `prompts.designed_view` 整理：保留课题、授课设置、授课对象、掌握情况、讲解安排、材料和图片解析，去掉范围检查、字符预算、检索记录、录入者和内部编号。整门课检索时，旧版写作方式的请求同样不带检索记录（查询、备选片段、教师移除的片段只存进 `generation_runs.retrieval`）。实际发送的内容仍可在「查看生成输入」里逐字核对。

针对旧流程输出的几条规则及原因：

| 规则 | 对应的问题 |
| --- | --- |
| 讲解安排里的 action、warnings 是内部说明，不得写进输出；没有诊断时安排前测题 | 同一句「暂无诊断数据」在一份讲义里换说法出现 4 处 |
| 必须写出重点（最多 2 条）、难点和本课不展开的内容，时间跟着重点走 | 一节 45 分钟的新授课做了四个完整推导，其中一个是前置知识 |
| 各环节分钟数之和等于课时；例题至少 4 分钟、练习至少 3 分钟 | 两道例题加三道练习只给 10 分钟 |
| 题目只在设计里写一次，环节正文不重抄 | 讲义、课件、题组各有一套题和符号 |
| 备课笔记口吻、阿拉伯数字、不写旁白和套话；篇幅只设上限 | 只数汉字的篇幅下限换来「四十五分钟」「需要特别说明的是」 |
| 所有字段的数学符号都用 LaTeX，全课一种写法 | 同一份设计里板书写 P(A\|B)、题目写 $P(A\mid B)$ |
| 环节正文不复述学情与对策，不改设计的时间 | 每个环节开头都重写一遍学情和「留作下节课」 |
| 发现设计前后对不上时单独写一行「待核对：」 | 提问里问「同除以 −2」，而题目最后一步是除以 4；模型在正文里绕着解释 |
| 单个学生按一对一辅导写（`lecture-design-tutor-v1.md`），程序检查环节里有没有巡视、小组、举手等词 | 给一名学生的课写着「巡视全班」「各组汇报」「全体必做、选做」 |
| 先写完题目再写学习目标，`checked_by` 只写真正考到这条目标的题；程序按词粗略比对目标和检验题 | 「能区分先验与后验」写由一道只套公式的练习检验 |
| 练习和作业不沿用例题的数据和结果，全课的时间和单位前后一致；程序比对题目里的数字 | 练3 和例2 是同一组数据，只把问法倒过来 |
| 答案（answer）只写最终结果，推导写进 steps；练习和作业各 1—3 步 | 教师用书的答案速查里是一整段解答 |
| 布置作业的环节最多 2 分钟 | 「布置作业」占了 5 分钟 |
| 参考题照用数据，题干、check 都不写“数据为自编”；程序删去题干和 check 里的这类说明，生成记录注明一次 | 学生学案的题干后面印着「本题数据为自编假设模型」 |
| 输出直接给教师和学生用：不写「依据诊断」「未诊断」「不预判」「待核对」「根据某某知识点」「本题考查」，不提 AI、提示词或程序；旧的观察写明月份；程序在设计和环节正文里查这些词 | 学情写着「依据诊断……（待核对……）」「未诊断，不预判」 |
| 每句话写完整；学科名词写中文（概率公式、分布函数），程序查省略号和 PMF、CDF 这类缩写 | 环节里写「分母应该是谁的概...」，学案题目写 PMF |
| 同一个结果在步骤、答案、检验和板书里写同一个值、同样的位数；程序比对 | 例1 答案写 0.1246，检验和板书写 0.1247 |
| 环节正文不提本课不展开的内容，不写「交代去向」「留作课后阅读」；关键句写成 讲：“……” | 三个环节各写一遍「留作课后阅读」，正文里出现「关键句可直接说」 |
| 追问要有确定的答案；比较两道题之前先核对两题的步骤；步骤编号按设计里的 step | 「例1、例2都用了递推和对立事件」（例2 没有用）、「第 3 步」指的是第 2 步 |
| 一对一辅导不写「选 B 的人」，写「学生如果选 B」 | 给一名学生的课写「选 B 的人」 |
| 环节正文不重抄提问的预期回答和追问；说原因、比大小先用本题的数核对；易错的后果实际算过 | 讲：“……”一字不差地重复下面印着的预期回答；「发生故障后它嫌疑更大」（后验 0.379 比先验 0.55 小）；「偏差超过 0.001」（实际 0.00096） |
| 课后检测不只换情境：数值要换，答案不能与做过的题相同；程序比对数字和答案 | 作业1 是「网站每分钟 4 次，求恰好 3 次」，课后检测是「客服每小时 4 次，求恰好 3 次」，答案相同 |
| 板书上的结果与题目算出的一致；每条目标至少由一道练习或作业检验；程序比对 | 板书写「练2：$P(C)=0.26$」，答案是 0.046；「能说出期望和方差」写由例1检验，例1只算概率 |

这些规则只约束写法和结构；内容是否正确、是否适合学生仍由教师判断。

### 按课堂设计上的课出配套题

配套出题的系统提示是 [quiz-v1.md](quiz-v1.md)；讲义是按课堂设计生成的，就追加 [quiz-lecture-v2.md](quiz-lecture-v2.md)（其他讲义仍追加 [quiz-lecture-v1.md](quiz-lecture-v1.md)）。版本标记为 `quiz-v1+lecture-v2`，按需要再带 `+json-v1`、`+class-v1`、`+replace-v1`（单独换一道题），输入结构为 `quiz-context-lecture-v2`：`lecture.design` 是课堂设计的摘要（符号写法、学习目标及检验它的题、重点难点、本课不展开的内容、课上和课后作业已经用过的题），`question_plan` 的每一题多一个 `objective`（学习目标编号）。模型要原样写回这个编号；程序核对编号、照抄检测（与课上的题几乎相同就退回）、符号统一和单选选项数值，不合格时带具体问题重试一次。学习目标由程序印在教师版每题下面，所以解析只写解法和检验：「对应学习目标 n」「本题与练1同类」「本题考查」「需教师复核」不写，写了程序也会删去；题目情境要合乎常识（均匀硬币是 1/2，人数是整数）。题干、选项和答案先算好再写，解析里不写「等等」「重新核验」「调整数值」这类改算过程；出现时程序退回重出（实际出现过：解析里改了三次数据，答案仍是错的）。题目是否真的在检测这条目标、答案是否正确，仍由教师判断。

## 旧版写作方式

新页面提交的讲义选择旧版写作方式时，会按「高级设置」追加两段，版本标记随之增加：

- `+rich-v1`：[lecture-format-rich-v1.md](lecture-format-rich-v1.md)，改用 LaTeX 公式、允许 Markdown 表格，并规定 ` ```figure ` 代码块里五种结构化图的 JSON 格式。它明确替代基础模板里「纯文本公式、不输出表格或代码块」的规定。
- `+sectioned-v1`：[lecture-sectioned-outline-v1.md](lecture-sectioned-outline-v1.md)，冻结的请求只要大纲（JSON 模式）。各章节的请求在运行时由冻结请求推导：去掉大纲段，换上 [lecture-sectioned-section-v1.md](lecture-sectioned-section-v1.md)，并在用户消息中加入 `target_section`、`section_brief`、`section_quota` 和 `outline`。章节提示词和各章节篇幅配额在提交时写入冻结上下文的 `sectioned` 字段（不发给模型），所以重试不受之后模板改动的影响。章节请求的版本标记为 `lecture-sectioned-section-v1`，重写请求为 `lecture-sectioned-section-repair-v1`。

不带 `generation_mode` / `lecture_format` 的请求（旧客户端、固定对照实验）不追加这两段，请求字节与之前一致。

## 设计原因与检查边界

| 规则 | 对应需求 |
| --- | --- |
| 按课程设定教师角色与共同目标 | 初中方程和大学概率分别有模板；个性化调整讲法不能替换共同目标，课程任务与学生状态独立 |
| 状态、诊断与近期证据一起输入 | 使用具体依据而非只按名字分档；未知不等于薄弱，保留判断时仍展示新证据 |
| 有 / 无画像模式 | 无画像不猜个体弱点，用同一课程、目标、材料和参数建立通用对照 |
| 固定五个章节 | 支持逐份比较；章节存在不代表其内容充分 |
| 材料 M 编号及范围关联 | 显示实际 SQL 查询材料；编号存在不能证明来源支持结论 |
| 运算、条件、术语与检验 | 针对原反馈的去括号 / 两步名称，以及新实验的事件符号 / 相等条件 / 归一缺失给约束 |
| Unicode 纯文本公式、明确分母 | 无需外部公式渲染；括住整个求和分母，避免纯文本歧义 |
| 汉字篇幅与禁止思考过程 | 初中 600—900；大学 v1 900—1400、v2 600—1000。汉字含标题，不计标点、字母和数字；历史要求保留 |
| 学生和材料作为数据 | 不执行资料中指令，不宣布生成导致掌握状态变化；后端也不更新学生状态 |

大学 v2 将同一观测事件、P(A)>0 / P(B)>0、交集为零时的相等反例、两例后验归一和分母写法明确化。真实 v2 仍可能漏条件或篇幅不足；词语提醒也可能命中标为错误的例句。全部发现保留，见 [实验汇总](../../experiments/2026-10-12-bayes/summary.md)。

动态消息用 JSON，包含本次 goal、课程任务、学生、状态与教学策略、各知识点最近 3 条证据、材料、scope_check 与 retrieval（本次材料取用方式的记录），大学任务增加固定 reference_examples。以顶层实际 goal 为本次要求，主题默认目标另存。无画像实际消息移除选中学生姓名 / 编号 / 说明、诊断、状态与策略，仅留下通用解释标识；共同课程名单元数据所有格子相同，数据库配对编号不进入选中学生字段。

旧expanded流程使用 `lecture_length_policy=expanded-v1`：常规建议 4000—6000 汉字，复杂内容约 8000 字；授课设置中简明提纲 1500—2500、常规讲解 4000—6000、详细讲解 6000—8000，题量增加时建议上限最多 8000。规则文件为 `lecture-length-expanded-v1.md`，追加在历史模板之后覆盖旧篇幅要求，提示词版本带 `+expanded-v1`。篇幅检查按新规则读取，旧快照继续按原规则检查。

新页面使用 `length_policy=duration-v2`，按时长、详略或自定400—6600汉字计算建议范围（约20%浮动、上限8000），提示版本带 `+teaching-v2`；输出额度按建议篇幅设置3000—16000 tokens。temperature=0.3、enable_thinking=false；网络等待由 `QWEN_TIMEOUT_SECONDS` 控制，默认600秒。旧expanded输入仍保留16000额度。tokens 是输出额度，不等同汉字数，也不保证模型一定达到建议篇幅。历史输入与按原输入重试保留原有参数。没有效果对比或最优性结论，重复输入不能保证同一输出。

## 留存与版本

`prompts.py` 只序列化一次。先将字符串与 SHA-256 写入 generation_runs，再把相同 UTF-8 字节发送。后台提交同时保存任务与完整输入；生成成功同时提交讲义与状态；失败保存分类及可读部分正文，不将失败正文视为完整讲义。

密钥、认证头、服务地址和原始异常不进入输入记录。SHA-256 是一致性校验，不是防篡改签名。按原输入重试复用原字符串、旧画像 / 来源 / 参数和版本，另建运行保留旧失败。新模板必须新增版本文件，历史输入始终读取实际记录。

旧 #1—#5 无完整 Prompt，不补造。网页最近展示 10 条运行，完整记录仍在库中。启动仅把遗留后台任务标为中断，不自动重新发送模型；旧同步 API 留存兼容。

## 程序与人工核查

math-text-check-v1 和 probability-text-check-v1 / v2 分课程检查章节、汉字、引用编号和资料关联，并显示逐处引用行号。大学新增概率条件 / 已知错误词语提醒，匹配不理解否定或证明结构。历史运行保留生成当时的范围和检查版本，新阈值不清除旧报告。

数学推导、例题、术语、引用支持、共同目标与诊断适配均列为教师检查项。程序通过不自动成为教师已审核；问题指向准确原文版本和行号，修订另存，现存助手草稿没有代勾审核表。

## PostgreSQL 实际用途

关系表和外键保存学生、知识点、状态、材料、证据、运行、任务、问题与修订。证据 / 教师判断、输入 / 任务、讲义 / 成功状态分别用事务同时提交；画像版本、审核事件与行锁防止旧页面覆盖。

上下文、用量、检查和差异保存在 JSONB，完整请求体单独使用 TEXT 保持原始字节。当前 6 名虚拟学生、6 个知识点、6 条材料。接口默认按知识点精确 SQL 查询；页面默认在此之上按学情从整门课补充片段，另有整门课检索和向量检索可选（向量检索先用知识点召回再用余弦排序），见 [功能说明](../../docs/features.md#材料取用方式与检索)。没有数据库性能对比；选型基于已实际使用的关系及一致性需求。表结构见 [schema.sql](../schema.sql)，实现与验证结果见 [VERIFICATION.md](../VERIFICATION.md)。

## 自建课程模板

`lecture-general-v1.md` 用于未继承专用课程规则的自建任务。新复制的数学／概率副本通过明确的 `prompt_family` 保留来源模板；仅修改课程名字不自动推断模板。它读取学段、课程、章节、任务层次与教学目标，适用于小学、初中、高中、大学及其他学科课程，使用通用案例和检验要求。自建任务即使命名为“大学概率论”，也不自动引入预设贝叶斯例题。原有数学和概率论模板及历史请求保持原样。


## 本次安排、预算与审核

`personalization_plan`保存知识点、原诊断、证据编号、讲解安排及待核对提醒。教师修改的是本次安排，不能借此写回诊断。`[K编号]`是定位标记，`[M编号]`和`[V编号]`才是来源；三者作用分别显示。无画像计划为空，系统规则和模型参数仍与有画像相同。

`lecture-budget-v1`在保存和发出请求之前限制材料与动态上下文；节选保留原文位置和指纹，未纳入材料编号单独记录。可核对每次实际消息，不能从字符预算推断精确token数。教师看到的正文引用会打开生成时快照，来源支持仍由教师判断。新检查版本带`+lecture-workflow-v2`，新授课策略再带`+teaching-v2`；旧报告不回写。

本轮固定对照存`lecture_experiments`和`lecture_experiment_cells`，实际生成继续使用`generation_runs`与原后台队列；固定输入、逐格保留失败和重启不自动重发的原则不变。
